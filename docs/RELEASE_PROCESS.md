# 易造发布助手正式发布流程

## 发布通道

- `alpha`：开发者自测，不交付普通用户。
- `beta`：一至三名同事在独立电脑试用。
- `rc`：冻结功能，只修阻塞发布的问题。
- `stable`：通过干净安装、升级、平台草稿回读和回退验收后发布。

## 唯一版本来源

所有发布身份由根目录 `release-manifest.json` 管理。修改后执行：

```powershell
node tools/sync-release-version.mjs
node tools/sync-release-version.mjs --check
```

禁止分别手改扩展与服务构建编号。扩展、服务、协议或构建身份任一不匹配时，工作台必须阻止真实草稿操作。

## 每次合并前

1. 需求与验收条件明确，公开发布默认禁止。
2. 新建独立分支并补充测试，不能删除测试绕过失败。
3. 执行扩展测试、类型检查、正式构建、安全检查和服务测试。
4. Pull Request 的 Quality Gate 全部通过。
5. 复核变更范围，确认不含令牌、Cookie、文章、Excel、用户路径、日志和浏览器资料。

## 发布候选

1. 从通过门禁的固定提交生成产物，生成后不得手工修改。
2. 记录提交 SHA、版本、构建编号、SHA-256、更新说明和已知问题。
3. 在干净 Windows 用户环境验证安装、首次配对、重启、升级、修复和卸载。
4. 使用专用测试账号逐平台保存一篇非敏感草稿，并完成回读核验。
5. 验证失败不会自动重试、不会公开发布、不会写 Excel、不会移动或删除文章。
6. 验证上一稳定版本可以恢复，配置与用户数据不会被覆盖。

## 分阶段放量

发布顺序固定为：开发者电脑 → 一台干净测试机 → 一名同事 → 三名同事 → 团队 → 外部用户。任一阶段出现阻塞问题，停止放量并发布新的候选版本，不在原产物上直接修改。

## GPL 分发要求

扩展分发包必须包含 `LICENSE` 和 `NOTICE`，并提供与发行版本对应的源码。易造品牌与新增代码可以由易造团队维护，但不得移除上游许可证和必要来源说明。
